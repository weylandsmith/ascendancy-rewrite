## 1. What the previous conclusion got wrong [verified]

media_probe.py reported sub-chunk types `UNK_0x0007` x875 (intro) and
`UNK_0x0007` x48 (logic) and concluded the payload was Ascendancy-specific.
0x0007 **is** the standard `DELTA_FLC (FLI_SS2)` chunk type — the probe's
name table omitted it (`FLI_NAMES` in media_probe.py). Re-walking with the
documented 16-byte `FRAME_TYPE` header (size,type,chunks,delay,reserved,
width,height), sub-chunks tile every frame of both files exactly and all
types are stock Autodesk Animator Pro chunks. The `num_chunks=0` frames
media_probe saw are EMPTY frame chunks (csz=16: header only, image
unchanged) — legal padding, not a different format.

## 2. Decode rules implemented (cited)

Primary source: compuphase.com/flic.htm, "The FLIC file format"
(documents Jim Kent's Dr. Dobb's Mar-1992 spec + Animator Pro chunks).
Cache: ~/.hermes/cache/web/www.compuphase.com-d5572e678e.md. Rules used,
each verified by zero-residue decode of EVERY chunk instance above:

- FRAME_TYPE (0xF1FA): 16 B header; `chunks` subchunk count is
  authoritative when non-zero; `delay` (ms) overrides header speed when
  non-zero. Empty frame chunk = keep previous image.
- COLOR_256 (4) / COLOR_64 (11): u16 packet count; packet = u8 skip,
  u8 count (0 = 256), count RGB triples; 64-level values are 0-63
  (scale <<2 to 8-bit).
- BYTE_RUN (15): per line u8 pack-count (IGNORED per compuphase 'Frequent
  errors' + BYTE_RUN section), packets until line width: i8 count;
  negative = literal run of |count| bytes, positive = replicate next byte.
- FLI_COPY (16): raw w*h bytes.
- DELTA_FLC (7): u16 number-of-lines (skips don't count). Line opcodes
  are words; top 2 bits: 10 = low byte -> last pixel of line, 00 =
  following word is the packet count, 11 = line skip. SKIP SEMANTICS
  ARE MEASURED, NOT TRANSCRIBED: count = -int16(op) (the ffmpeg
  flicvideo.c reading). compuphase's '(op & 0x3FFF)' would skip 16212
  lines at intro65a frame 1 (opcode 0xFF54) and desync the walk; the
  negation gives 172 and every frame then tiles. Packet = u8 column
  skip + i8 count: positive copies that many WORDS (two palette
  pixels), negative replicates the one following word, zero = extra
  skip (the >255-skip split pitfall). Trailing skip opcodes after the
  last counted line are legal and consumed.
- PSTAMP (18): 12 B header; embedded chunk of type 18 carries the 256 B
  six-cube translation table, other embedded chunk is the stamp image.
  Structure-validated only here; the reimplementation does not display
  the stamp.

## 3. Cross-validation contract for the C++ port

Frame state hashes pin decode identity for `rewrite/src/formats/flic.*`:
`rewrite/tests/data/flc_golden.tsv` (regenerate:
`python3 scripts/flc_probe.py --hashes rewrite/tests/data/flc_golden.tsv`;
columns file/frame/sha256/fnv1a64). The C++ test replays every frame of
`game/logic.flc` and compares FNV-1a-64 over (640x480 palette indices,
then 256 RGB triples) — the exact byte order of the Python generator —
so a decoding divergence fails at the first differing frame.

A second independent invariant is already implied: every chunk consumed
its exact size (a wrong opcode interpretation desynchronises the chunk
walk on the very next instance). A third: frame 600 of intro65a.flc was
rendered to `docs/assets/flc-intro-frame600.png` and visually inspected
(coherent artwork: rust-coloured planet + moon + glowing lane network).
