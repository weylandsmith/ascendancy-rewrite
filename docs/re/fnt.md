# .fnt vendor font codec (OQ-017 CLOSED)

Generated by `scripts/fnt_probe.py`; gate stage 3p re-validates every
invariant below on all 384 vendor glyphs (exit code is the assertion).

## Container [verified 384/384]

```
u32 magic 0x00002e31 ("1." + u16 0)     same 1.x family as .shp
u32 N = 128                              glyph count
u32 HEIGHT                               8 (sm) / 11 (big) / 39 (intro)
u32 255                                  constant, all fonts
u32 offsets[N]                           strictly increasing, file offsets
glyph[i]  u32 width; width*HEIGHT bytes  1 byte per pixel, row-major,
                                         NO stride padding
                                         (last glyph body ends at EOF)
```

- `extracted/ascend01/data/smfont.fnt`: 4792 B, h=8, ink alphabet {0xf3}
- `extracted/ascend01/data/bigfont.fnt`: 7376 B, h=11, ink alphabet {0xf3}
- `extracted/ascend02/data/intro.fnt`: 63908 B, h=39, ink alphabet {0xf0, 0xf1, 0xf2, 0xf3, 0xf4, 0xf5, 0xf6, 0xf7, 0xf8, 0xf9, 0xfa, 0xfb, 0xfc, 0xfd, 0xfe}

## Pixel semantics [verified + vision-confirmed]

- `0xFF` = background. Any other byte = ink. BRIGHTNESS INCREASES
  WITH BYTE VALUE: measured edge/interior census of intro.fnt —
  interior fraction of 0xF0..0xF5 = 0.022 (stroke fringe),
  of 0xF7..0xFD = 0.417 (stroke interior). An AA face puts
  its weak values beside the background and strong values inside
  strokes, so higher byte = brighter ink. (255-value) is the
  darkness of the BYTE, not of the rendered ink; the 2026-10-04
  text here conflated the two.
- smfont/bigfont use the SINGLE ink value `0xF3` throughout: solid
  faces (1-bit in practice). intro.fnt uses the full `0xF0..0xFE`
  ramp — anti-aliased 39 px intro face. Both render as clean,
  legible letterforms: docs/assets/fnt-smfont-sheet.png,
  fnt-bigfont-sheet.png, fnt-intro-sheet.png (independent vision
  readout: "all characters clearly legible", intro aliased edges,
  not scrambled).
- Unimplemented glyphs (all-0xFF body): index 0..31 always, plus
  `@ ^ { | } ~` in sm/big. space (32) has width but no ink.
- Widths are per-glyph u32 (variable-width face): space=4/5/16,
  A=6/8/22 (sm/big/intro). No side bearings: advance == width.

## Why the old probe failed [verified]

docs/re/media.md originally recorded payload 52 B for w=6: that came
from treating the slot as pitch-based bits (ceil(6/8)*8*1 != 48+4).
The truth is byte-per-pixel — 6*8 = 48 body bytes + 4 header = 52,
which is exactly the observed length once read as bytes, not bits.
