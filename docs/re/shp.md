## 1. Container [verified 208/208 files]

```
  +0x00  4B   magic "1.10"
  +0x04  u32  shape count N (observed 1..76)
  +0x08  u32  table size = 8*(N+1)   <- invariant on every file
  +0x0C  u32  reserved, always 0
  +0x10  (N+1) x u64 slots; record 0 sits at table_end and has no slot;
         slots 0..N-2 = strictly increasing record pointers (records 1..N-1),
         last record -> EOF. Slots N-1, N = library metadata, never inside
         the data area (208/208): u16x4 + i32x2, e.g. bullet04 (39,39,20,20)
         and (-10,-6) — shape box + signed hotspot is the obvious reading,
         unconfirmed.
```

Container self-consistency (positive spans exactly covering the data area) is
asserted inside `parse()` — a violation aborts generation, and gate.sh stage
3c runs this script.

## 3. Record headers: two prefix widths, and why that blocks the codec

Measured across the corpus (first three records of each library), counting
how many records admit each dimension packing:

| record | records seen | u32 w + u32 h valid | u16 w + u16 h valid |
|---|---|---|---|
| rec0 | 208 | 198 | 0 |
| rec1 | 163 | 0 | 163 |
| rec2 | 160 | 0 | 160 |

Record 0 packs its dimension pair as two u32s (the u16 reading fails there:
the second u16 lands on the high half of w and reads 0 — listbox rec0 is
`18 00 00 00 18 00 00 00` = u16s (24, 0, 24, 0)). Records 1+ pack it as two
u16s. After the rec1+ u16 pair, 39 libraries have a zero u32 and 124 have
two more u16 values (sample 9endgame rec1: 79, 285, 40, 143), so the
prefix LENGTH at rec1+ is not established, only its packing. The grammar
search (section 4) therefore tries header sizes 4/8/12 independently.

Concrete samples:
- listbox.shp rec0 @56 `18 00 00 00 18 00 00 00` = u32 24 x u32 24, then the
  stream `32 67 00 03 67 2e f2 ...`; rec1 @402 `18 00 18 00 00 00 00 00` =
  24 x 24 packed as u16s, then a zero u32.
- bullet04.shp rec0 reads 10x11 (110 raw px) but spans 331 B, and its
  library metadata slots hold `f6 ff ff ff` / `fa ff ff ff` = signed -10/-6.
  Shapes carry signed offset-like data; raw w*h does not size a record.

Opaque record-0 libraries:
- 10 libraries do NOT put readable u32 dims at table_end, in 2
  byte-identical header variants:
  - rec0 `bb ff ff 7f bb ff ff 7f 8b 00 8b 00 46 00 46 00` — 9 libs: expl03.shp, expl04.shp, expl07.shp, expl08.shp, sg37expl.shp, sg45expl.shp, sg47expl.shp, sg49expl.shp, sg66expl.shp
  - rec0 `12 00 00 00 fb ff ff ff 01 08 03 02 00 01 08 05` — 1 libs: sg64expl.shp
  0x7FFFFFBB is positive as u32 AND as i32 (2147483579), or reads as
  an i16 pair (-69, 32767); in expl03 the following bytes are u16 139,
  139 then u16 70, 70 then i32 -56, i32 -23. No reading is
  confirmed — flag as a header variant, do not model it.

## 4. Grammar search: negative result [machine-checked]

Five RLE grammars (`GRAMMARS` in scripts/shp_probe.py) x header size 4/8/12
x u16/u32 dim readings, over the 12 smallest libraries. Acceptance required
consuming EXACTLY the span of every record in a library — exact-span is the
discriminator; grammars that merely avoid overflow would match noise.

Result: 0 combinations survived.
Resolution path: the exe shape loader (P2 subsystem "UI/render
primitives") settles this directly — start from xrefs to the .SHP path
strings listed in section 1.

Measured entropy per shape record 3.4-3.9 bits/byte over 20-31 distinct byte
values (listbox.shp) -> light RLE over palette indices, not LZ.
